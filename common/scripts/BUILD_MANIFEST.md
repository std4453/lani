# 构建指纹的设计

manifest 描述源码构建输入，供 CI 复用镜像和部署端比较版本。生成器读取 Git 暂存区或完整提交，因此结果与本机依赖安装、构建缓存和网络无关。提交操作见[贡献指南](../../CONTRIBUTING.md#提交与检查)。

每个应用包含 Rush 依赖闭包及部署额外包含的项目。跨包源码和符号链接目标必须声明依赖，才能让变化传递到消费者。所有 `.md`、`.mdx`、`.markdown` 文件（扩展名不区分大小写）、各层级 `docs/` 目录、根目录 `development/` 和文档 workflow 被排除。文档目录包含截图等附件，仅用于说明；应用源码、配置示例、迁移 SQL 和运行资源保留在这些目录之外并参与指纹。新增目录或调整依赖时，用 `explain` 核对实际范围。

文档新增、修改、移动和删除均保持应用指纹不变。GitHub workflows、发布规划、指纹生成器与其他通用工具源码不参与应用指纹；工具的包配置、编译配置及锁定依赖继续参与相关应用的构建输入。共享输入按明确清单保留 Node/Rush 安装与编译配置、部署配置和 Docker 上下文规则，包内 Dockerfile、源码、配置及运行资源仍属于各自应用。修改指纹算法时仅由实际输入或算法版本改变指纹，不因生成器文件本身变化而整体失效。CI 是否跳过应用流程仍按[贡献指南](../../CONTRIBUTING.md#pr-与-ci)中的事件范围判断。

算法 v2 按应用截取 pnpm 9 锁文件中的 importer、递归可达的 package 和 snapshot，包含开发依赖、可选依赖及 peer 实例。安装设置、overrides 和 pnpmfile 校验和属于共享输入。这样一个包独有的依赖变化不会让所有镜像失效；升级算法本身会改变全部指纹。

外部大模型匹配器内置于 API Server，其源码与提示词作为 API 构建输入；提示词由 Nest assets 复制到运行目录。`anime-matcher` 继续提供可独立部署的 Python 服务，all-in-one 仍内置该实现。Python 源码、依赖声明及模型清单按包目录纳入；Python 尚无传递依赖锁文件，指纹只能证明已提交输入相同，不能证明重新下载的依赖与过去完全一致。

CI 仅构建缺失的 `fp-<fingerprint>` 镜像，并以 OCI labels 记录实际构建 SHA、指纹及 run/attempt。标签用于追溯，可信度仍依赖发布权限。保留已发布指纹标签；需要更新基础镜像等外部输入时，修改构建配置产生新指纹。完整重跑会重新规划，避免单独重跑旧 job 覆盖既有产物。
