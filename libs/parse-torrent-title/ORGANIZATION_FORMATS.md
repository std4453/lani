# 制作组随机测试格式目录

版本 1 的格式独立于新识别器整理，并在首次随机评分前固定。版本 2 在保留全部 32 类原始模板逻辑的基础上，依据原始语料与独立覆盖审查增加 4 类，扩展在首次真实保留集和新 seed 验收之前固定。依据为原始 600 条人工盲审中出现的发布方式，以及人工确认的联合组、技术信息误当组、职责信息误拆分错误家族。生成器不读取识别器、现有字幕组词典或验收保留集；不得因识别器失败而移除格式。

## 发布格式

`G`、`H`、`K` 表示独立生成的未知组名；`E` 表示有「字幕组／字幕社／制作组」明确后缀的未知组名；`T` 表示独立生成的作品名。下表中技术、集数信息均会变化。

| format ID            | 结构                                | 观察依据与目的                              |
| -------------------- | ----------------------------------- | ------------------------------------------- |
| square-free          | `[G] T - 01 [技术]`                 | ANi、NC-Raws 等无后缀名称的常见结构         |
| square-title-block   | `[G][T][01][技术]`                  | 组块与作品块相邻                            |
| corner-free          | `【G】T - 01 [技术]`                | 中文书名式包装                              |
| corner-title-block   | `【G】【T】【01】[技术]`            | 幻樱等连续包装方式                          |
| round-explicit       | `(E) T - 01 [技术]`                 | 圆括号包装的明示组名变体                    |
| wide-round-explicit  | `（E）T - 01 [技术]`                | 全角圆括号包装变体                          |
| joint-amp            | `[G & H] T`                         | 原始人工样本中的联合发布                    |
| joint-wide-amp       | `[G＆H] T`                          | 猎户随缘发布组等错误家族                    |
| joint-cross          | `【G×H】[T]`                        | 极影与动音漫影联合发布                      |
| joint-plus           | `【G+H】T`                          | 极影与辉夜汉化联合发布                      |
| joint-mixed          | `[G＆H & K][T]`                     | 悠哈璃羽、JOJO 吧、LoliHouse 混用分隔符家族 |
| adjacent-square      | `[E][E][T]`                         | 相邻独立组块的组合变体                      |
| adjacent-corner      | `【E】【E】T`                       | 相邻全角独立组块的组合变体                  |
| prefix-resolution    | `[1080P][G][T]`                     | DBD 错误家族，技术前缀不是组名              |

| role-audio           | `[G合成&音频压制][ViuTV粤语]T`      | 同上，音频职责                              |
| role-reencode        | `[G合成&二次压制][代理商粤语]T`     | 同上，二次压制职责                          |

### 版本 2 新增格式

| format ID               | 结构                                      | 金标与扩展理由                                                                                           |
| ----------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| scene-dual-signature    | `[G] T - 01 [WEB-DL 1080p AVC AAC-H]`     | 前缀组和技术 token 紧邻尾签共同署名，预期 `[G, H]`；原始语料已有前缀字幕组加 scene 源组双署名，v1 未覆盖 |
| bilingual-single        | `[中文未知字幕组(UnknownLatin)] T`        | 中英括注为同一组的名称，完整内容是单个 part，不能丢掉括注或拆成两组                                      |
| decorated-single        | `[❀G❀] T`                                 | 原始 600 条中出现装饰符，组名必须原样保留                                                                |
| negative-anonymous-role | `[个人翻译／个人压制／自压／转载][T][01]` | 每次随机选择一种匿名职责；没有可归属的名称，金标为空集合                                                 |

scene 尾签由独立随机字母和数字生成，可包含点或连字符；金标直接来自两个生成参数。中英括注中的中文和英文均独立随机生成，整体作为一个组名。装饰组名的金标包括装饰符。匿名职责的金标固定为空，不依据识别器输出调整。这四类为覆盖缺口的追加，不替换任何 v1 格式或降低门槛。

圆括号、相邻组块和尾部标签属于从常见语义组合出的扩展格式，并非声称原始 600 条均有对应实例。无后缀的任意圆括号块或任意尾部方括号块与别名可能无法仅凭标题区分，因此这些位置只生成明示组名。无括号组名也只生成有组后缀且用星号分隔的结构。不会把「标题里任何未知词」直接标成组名。

## 随机化与评分

使用 `node scripts/organization-random-corpus.cjs --seed <任意字符串> --count 10000` 输出 NDJSON。每条包含 `id`、`title`、`expected_groups`、`format`。相同 seed 和 count 结果完全相同，生成过程没有时间、文件、网络依赖。每轮独立洗牌所有 36 个格式，使各格式样本量相差不超过 1；固定格式后可用全新 seed 验收。

未知组名独立随机拼接辅音字母或汉字，覆盖纯英文、中文、中英混合、空格、连字符、数字开头和数字结尾。所有名称带五位随机数字，避免复用真实已知组名；绝大多数方括号正例没有 Subs 或字幕组后缀。片名使用另一套词料、英文别名和随机数字生成，金标直接保留生成的组名数组，不依赖被测解析器。联合组按完整集合比较、顺序无关，保留原拼写；比较前仅归一空白和全角 ASCII 并去重，漏组、额外组、职责污染均算整条失败。

CI 固定 seed `organization-ci-v2` 生成 10000 条，要求总准确率及联合组准确率均至少 95%；无组对照要求零误报。报告全部 format 的样本数、命中数和准确率，失败示例限制输出数量。格式目录和生成器冻结后，验收应另选未使用 seed 生成至少 10000 条；不能只复用 CI seed 声称泛化通过。
