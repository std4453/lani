# 外部大模型季度匹配

lani 可在 API 进程内通过兼容 Chat Completions 的接口匹配资源所属季度。匹配器只接收调用方提供的完整目录快照、近期候选和标题，不读取业务数据库，不处理下载或定位单集。目录版本、刷新节流、候选计算、队列及结果落库继续由原匹配模块负责；独立 anime-matcher 与内置实现共用同一后端接口。

## 配置与运行边界

选择 `matching.backend: llm` 后，`matching.llm` 配置供应商、模型和匹配策略。所有外部模型调用经过共用的 `LlmService`：顶层 `llm.concurrency` 默认 2，`llm.timeoutMs` 默认 45000；匹配器不另建并发池。一个匹配操作默认最多 100000 ms，包含公共限流器中的排队、退避及两个阶段；达到截止时间会中止剩余调用。

```yaml
llm:
  concurrency: 2
  timeoutMs: 45000
matching:
  enabled: true
  backend: llm
  llm:
    apiBase: https://your-provider.example/v1
    apiKey: <通过部署配置注入>
    model: your-model
    deadlineMs: 100000
    fallbackEnabled: true
    firstParameters: {}
    reviewParameters: {}
```

`apiBase` 是供应商 API 基础地址，由 SDK 拼接 Chat Completions 路径。项目不默认选择供应商。DeepSeek 官方路由可使用 `apiBase: https://api.deepseek.com`、`model: deepseek-flash`，首轮参数设为 `thinking: { type: disabled }`，复核参数设为 `thinking: { type: enabled }` 与 `reasoning_effort: high`。模型名及扩展参数以供应商合同为准，凭据不写入公开配置或日志。

首轮默认 `temperature=0,max_tokens=128`，复核默认 `max_tokens=8192`。两阶段固定 `stream=false,response_format={type: json_object}`，扩展参数不能覆盖模型、消息或这些固定项。关闭 `fallbackEnabled` 可用于首轮对照。`matching.catalogDebounceMs` 在 LLM 模式默认 `0`，external 模式默认 `600000`（10 分钟），显式配置优先。目录仍每分钟检测一次，只有实际内容变化才刷新；已持久化的等待窗口不因配置变化重新计时。

保留独立匹配器时选择 `matching.backend: external` 并配置其 `endpoint`；all-in-one 默认仍使用原 anime-matcher。

## 两阶段判断

所有目录统一使用两阶段流程：首轮只给近期候选的 ID、完整名称、年份与季度，拒答再用完整目录独立复核。小目录也保留这一流程。季度缺失时，内置 LLM 可用有效作品首播日期补候选窗口；已有季度优先，独立匹配器的窗口规则不变。

声明集数冲突与可重试技术故障仍可触发复核。标题季数标记和跨季合集识别由 `@lani/parse-torrent-title` 共用；matcher 决定是否复核或跳过。只有发布者季数或原标题明确季数、且单集编号超出声明集数时才检查冲突；命中该条目真实编号摘要可免去此次复核。特别篇、OVA/OAD、Recap 等标题仅接受 `sp.sort` 作为免复核证据。整数范围不包含中间小数，未列出的编号保持未知，不据此硬拒绝。编号证据不验证篇章身份，不能防止模型把新篇误认为目录已有前篇。

目录摘要只读取数据库已有 `bangumiSort`，没有 sort 的剧集不参与摘要。普通剧集按 `episodeNumber` 和 sort 分别形成集合，SP 仅提供 sort；去重、排序并合并连续整数，保留断点与小数。例如：

```json
{"numbers":{"episode":{"local":"1-12","sort":"14-25"},"sp":{"sort":"13.5"}}}
```

不向模型提供逐集标题或日期，不把两个编号集合当作一一对应的 offset 表。摘要参与目录版本和提交前核验，只有去重、排序、区间合并后的摘要实际变化才更新目录并按配置 debounce，重复同步不刷新；逐集标题、放送时间及行顺序变化不会使摘要失效。声明集数与首播日期继续来自作品级元数据，不能根据已同步剧集数或最早单集日期推算。匹配过程不请求 Bangumi、不回填业务数据。两个后端统一接收可选 `numbers` 字段，沿用 v2 协议；旧外部 matcher 可忽略该字段。

提示词位于 [prompts](../src/torrent-match/llm/prompts)，精简首轮不受编号变化影响，完整复核携带摘要。两阶段均不接收前次答案，供应商缓存和计费仍由供应商决定。空完整目录不产生付费调用；已解析的集数范围和标题明确跨季合集不进入单集季度匹配，单个总集篇仍可参与季度归属判断。

严格接受正常结束的 `{"s":"候选ID"}` 或 `{"s":null}`；额外字段、重复键、目录外 ID、截断及字符串 `"null"` 都属于格式错误。返回仅为季度 ID 或拒答，不给出精确剧集、offset 或校准置信度。

每阶段最多重试一次连接、429、5xx 或格式错误，完整匹配最多四次实际调用；有效拒答不作技术重试，鉴权等不可重试错误直接失败。最终技术故障保留为失败，不能伪装成拒答。业务队列不再额外自动重试放大次数。

## 观测与验证

Nest 日志记录 `llm_prompt` 提示词摘要、`llm_attempt` 阶段/次数/耗时及供应商返回的 token 和缓存用量，失败记录安全的错误详情。响应 `diagnostics` 保存用量与耗时，没有提供的计量字段保持缺失。密钥、原始提示词、模型解释和思考正文不进入日志；未知异常保留脱敏后的栈或原因，向调用方返回通用失败。

模型版本根据固定提示词和非凭据配置生成；远端模型别名可能更换权重，因此不能由该版本证明供应商权重不变。账单余额和最终扣款仍需从供应商核验。

在 `apps/api-server` 执行：

```bash
node ../../common/scripts/install-run-rushx.js test --runInBand src/torrent-match/llm/llm-matcher.spec.ts
```

回归使用合成目录和替代 `LlmService`，覆盖冻结提示词、统一两阶段路由、编号压缩与类型边界、两阶段、重试上限、总期限、取消、快照替换及严格结果校验，无付费调用。共用 SDK 传输和限流由 `LlmService` 的独立测试覆盖。

## 既有研究与验收

2026-10-29 的研究使用脱敏季度目录和既有标题回归集，补充 Nyaa 发布标题。目录共 879 个作品季度；默认首轮近期窗口、全目录 high 复核方案在 A 回归集正确 899/900（99.889%），B 回归集 191/191，新增 Nyaa 样本 19/19，困难开发集 115/116（99.138%）。A/B 曾用于前轮研究，困难集参与过提示词开发；这些是回归结果，不能视为独立盲测或线上准确率保证。

同日部署验收在隔离测试环境的 29 季目录下，冻结 2026-10-25 至 2026-10-27 的最近 400 条资源：379 条可明确判定样本全部正确（377 条目录外拒答、2 条命中），21 条重复目录或分部信息不足的样本单列。另经标题筛选的 22 条补充正例全部命中；它们不用于估计总体召回率。两次最终超时保留为任务失败，经人工定向恢复后共 422 条完成。此验收基于先前 Python 运行版；独立 Node 版及当前内置版迁移保留相同提示词和判断流程，以各自回归测试核验，历史实测不代表迁移版本已经重新进行真实模型验收。


2026-11-01 的编号摘要候选在 1,000 条单资源扩样中，按复核后 983 条明确标签，原方案与候选均为 975/983；复核 311→289，已知输入 token 减少 1.61%、输出减少 9.89%。候选相对原方案有 3 条改善、3 条退化，不代表逐场景更优。标注使用 AI 辅助及来源复核，保留了修订前分数；样本集中于近期资源，同作品多版本并非独立样本。这些是研究实现的离线回放，当前 TypeScript 实现由协议与路由回归验证，不等同上线验收。

残留 8 条错例独立补充 Bangumi 编号后，每条各重复 3 次：3 条前篇范围冲突从 0/9 变为 9/9 正确，另 5 条篇章身份误判仍未稳定解决。因此采用真实编号摘要和两阶段机制，同时保留篇名映射仍可能错误的限制；没有采用额外强化 SP 拒答的实验提示词。
