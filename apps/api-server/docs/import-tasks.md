# 下载和导入任务

下载、单集导入、批量导入共用任务管理、后台执行、取消和重试。导入接口创建任务后立即返回任务 ID；关闭详情弹窗不会停止任务。批量导入只能选择同一季度的不同剧集，源路径也不能重复。

## 关联与恢复

`Task` 保存任务类型、workflow、下载输入和单集产物。批量导入的 `batchEntries` 按确认顺序保存内部条目 ID、剧集 ID、导入源路径及逐项产物，条目 ID 在创建后保持不变。`TaskEpisode` 仅包含任务 ID 与剧集 ID，用于关联查询。删除剧集会移除关联、清空单集任务的目标引用，但保留任务及已保存产物。

导入步骤依次为：寻找视频文件、导入文件、写入元数据、刷新 Jellyfin、完成。批量执行层等待全部在途操作，有任一失败就不进入下一步。它使用 `workflow.steps[].checkpoint.entries[内部条目 ID]` 保存逐项检查点及 `completed`，重试跳过成功项。单集任务继续使用根检查点，不包装成批量结构。runner 只提供基于最新快照的原子更新，批量层负责合并自己的检查点和任务条目；发布模块集中解释发布标记，在持有剧集锁的同一事务中检查冲突、写入占用或提交剧集关联与完成标记。

取消唤醒所有等待项，并等待在途文件操作收敛；已经落地的文件和已经发布的关联保留。暂存文件和 Jellyfin 等待项按任务、内部条目区分，迟到结果不能写入新尝试。下载和导入共享剧集发布互斥；媒体池登记、版本替换与历史回填遵循[媒体池设计](../src/media-pool/DESIGN.md)，已完成任务不永久阻止同集替换。导入完成不发送下载发布事件，不触发下载通知或 Lania 发布同步。

导入任务的「任务信息」仅展示创建时间和类型。批量详情通过「任务流程」「导入列表」页签切换，右侧显示自动刷新状态。导入列表用表格展示源文件和最终剧集映射，各字段可独立复制；路径显示相对目录，复制时保留完整路径。概览与页签内容分别滚动，页签栏作为分界，不额外添加分割线。导入表格贴齐弹窗两侧及页签栏，单元格左右留白与概览对齐，表头在列表滚动时固定顶部。确认导入弹窗最大宽度为 740px。任务列表的固定内容列预留 16px 余量并单独计入 padding，剧集与失败原因按 3:2 分配剩余空间，分别保留 240px、160px 的最小宽度；长剧集标题在单元格内换行。

## 自动偏移

偏移只产生确认表单初值，不自动提交。最终映射在创建任务时保存，执行与重试不重新推断。手工改映射或删除确认行不会触发重新匹配；删除行不改变上一步的文件选择。左下角偏移控件默认填入推断结果，可按 ±1、±12 或直接输入调整；输入在回车或失焦时应用。输入框使用标准 disabled 背景色 token 与按钮区分，仍可正常编辑；文件编号与种子标题共用主色文字、半透明主色背景的高亮组件。界面采用 `目标编号 = 文件编号 + 调整量`，例如 13→1 显示 −12。调整只影响未手动选择的普通单集，手动选择可指定特别篇。偏移不限制范围，按钮始终可用；超出范围或落入编号空洞时清空该行，下次调整仍按原始文件编号重新匹配。「重置」恢复偏移 0 并清除所有手动标记，未解析出单集编号的行清空，但不会恢复已删除的确认行。手动调整不受自动推断的最小偏移限制。未全部匹配时仍可点击导入，未选择的输入框会标红，补齐且无重复剧集后才能创建任务。

评分函数仍约定 `目标编号 = 文件编号 − d`，界面显示其相反数。选择至少 6 个文件且识别出至少 6 个不同的普通单集编号时才推断非零偏移。普通 `.5` 编号参与匹配；SP、OVA、OAD 使用各自类型直接匹配，范围和无法解析的文件交给人工。重复普通编号阻止自动偏移。

候选包含零及所有整数差值。候选必须让全部已识别普通文件一一对应实际存在的季度剧集；越界、编号空洞均无效，不裁掉离群文件。读取完整季度，编号优先使用 `episodeNumber`，缺失时兼容 `index`。

缺集集合 M 为没有可用媒体且没有进行中任务的普通剧集；失败、已取消任务不阻止计入 M。候选目标集合为 T，文件数为 n，评分为：

| 分项           | 分数                                   |
| -------------- | -------------------------------------- |
| 缺集命中率     | `40 × #(T∩M) / n`                      |
| 缺集覆盖率     | `10 × #(T∩M) / #M`，M 为空时为 0       |
| 季度边界       | 命中首、末编号各加 3                   |
| 接近 12 倍数   | `8 × (1 − distance(d, 12ℤ) / 6)`       |
| 原编号         | d 为 0 时加 8                          |
| 偏移距离       | `−min(8, abs(d) / 48)`                 |
| 进行中任务冲突 | `−20 × 目标中运行中或取消中任务的比例` |

最高分为零时保留原匹配；非零候选只有在 `|d| ≥ 6` 且领先第二名至少 8 分时才自动应用，唯一有效候选无分差限制。±1 ～ ±5 仍参与排名，但不会自动应用，也不会跳过它们选择较低分的大偏移。无有效候选或分差不足时，仅保留原编号能精确匹配的行。

回归用例包括动物狂想曲历史映射的 12、刃牙道历史映射的 13，以及结构派生和人工构造的 11、60、−12、不连续缺集、歧义缺集、小偏移、元数据空洞、离群文件和重复编号。22 个场景与 29,568 组边界检查用于验证规则，不代表真实资源匹配准确率。

## 迁移与接口

迁移 `20261016000000_task_episodes` 只新增任务的导入字段、简单关联表及历史单集关联回填。现有任务的输入、产物和 workflow 原位保留，不搬迁或改写；历史同步导入记录不回填。没有 workflow 的历史任务继续展示完整流程，包括末尾的「完成」节点。

GraphQL 的原单集字段继续来自 Task，批量输入与产物读取 `batchEntries`；`taskEpisodesByTaskId` 只提供剧集关联。`tasksByEpisodeId` 反向查询覆盖下载及全部导入任务，单集目标的原生反向查询命名为 `singleTasksByEpisodeId`。`importSingle`、`importMultiple` 返回创建的任务 ID，调用方通过详情和状态轮询观察执行结果。

发布时需停止旧 API worker 后迁移，并同时更新 API、Data Server 和 Admin；批量导入的新字段与接口需要前后端一起更新。本次没有新增运行配置。

## 验证

除各包 Jest 测试及构建外，在隔离的本地、数据库名以 `_test` 结尾的 PostgreSQL 上运行 API 集成测试：

```bash
cd apps/api-server
LANI_LIFECYCLE_TEST_DATABASE_URL='postgresql://localhost/example_test' rushx test --runInBand
```

集成测试覆盖真实事务上的并发检查点、任务内逐项产物、发布互斥和删除剧集后的保留行为。Jellyfin 和下载器使用可控替身验证取消及迟到响应。任务列表签名轮询同时覆盖无筛选与清除筛选，避免发送后端拒绝的空 `filter`。
