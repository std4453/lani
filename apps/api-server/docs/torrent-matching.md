# 种子季度匹配设计

API 负责目录生命周期、候选范围、入队和结果提交，worker 负责推理。用户配置见[使用文档](../../../docs/docs/torrent-matching.md)，通信合同见[协议 v2](matcher-protocol.md)，执行恢复见[后台队列设计](../src/background-queue/DESIGN.md)。

## 输入与目录

种子入库与匹配入队在同一业务事务中完成，重解析也通过统一入口更新。只有标题、发布时间、名称和剧集编号等推理输入变化才使旧结果失效；字幕抓取等独立元数据变化保留原结果。PostGraphile 隐藏通用写入口，避免绕过业务事务。直接 SQL 维护不会隐式匹配。

目录版本由规范化内容计算，权威快照和静默窗口截止时间保存在数据库。重启继续原有截止时间，配置变更只影响之后发现的目录变化。模型不使用逐集日期，因此单集编号和日程变化不影响目录。Bangumi 剧集同步会同时读取一次作品信息，仅更新独立声明集数和首播日期；这两个字段变化时按正常目录流程生效，保留其他作品信息和人工播出设置。

目录 active 与 desired 分开保存，使构建失败时仍保留可恢复基线。完整目录存在待生效变化时，匹配队头等待，防止全目录复核使用过期作品信息。构建期间暂停匹配，避免旧快照反向覆盖新 worker 缓存。缓存丢失时由 API 上传保存的 active 目录恢复，失败任务保留供显式处理。

首轮候选按资源发布时间、公历季度、时区和相邻季度配置选择，请求只发送近期 `candidateIds`，完整目录由 `catalogVersion` 引用。API 不区分 matcher 的实现；替换服务地址即可切换，模型参数、端点及回退开关由 matcher 自身维护。完成结果不会因目录、模型或配置变化自动重评，避免无意改变既有业务关联。关闭匹配会暂停生产和消费，再启用时保留原队列但不补录停用期间的新种子。

## 结果与取消

模型正常拒答与组件故障分开：拒答完成为 NO_MATCH，故障保留 PENDING，由队列记录失败并继续处理后续种子；失败记录保留供显式恢复，不自动重试。结果保存关联、完整 matcher 响应及本地输入摘要。阶段、版本和诊断等可选扩展由 matcher 定义，API 原样保存；matcher 负责控制扩展内容，不发送密钥或模型思考正文。提交前乐观核对种子输入和完整目录，并沿用队列 revision 保护，拒绝已被新输入取代的结果；季度被删除时关联置空，但历史 MATCHED 保留，避免把对象删除改写成模型拒答。

用户取消关联保存 DISMISSED，并与生产和结果提交采用相同锁顺序删除任务。在途旧结果无法覆盖取消意图，后续自动或批量重评也跳过已取消记录。

管理员可通过鉴权 `enqueueTorrentSeasonMatches` 分批指定 Torrent ID。默认仅处理未进入匹配的记录，`rematch: true` 显式允许重评并恢复选中种子的失败任务，仍跳过已取消记录。该入口用于明确范围的维护任务。

## 验证重点

数据库回归覆盖事务回滚、并发入库去重、重解析失效、取消和旧 revision 提交。传输回归覆盖缓存丢失恢复、非法返回、请求取消及不确定结果；HTTP 请求不自动重试，以免掩盖目录状态变化。测试环境与命令见 [AGENTS.md](../AGENTS.md)。
