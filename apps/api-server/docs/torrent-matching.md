# 种子季度匹配设计

API 负责目录生命周期、候选范围、入队和结果提交，worker 负责推理。用户配置见[使用文档](../../../docs/docs/torrent-matching.md)，通信合同见[协议 v1](matcher-protocol.md)，执行恢复见[后台队列设计](../src/background-queue/DESIGN.md)。

## 输入与目录

种子入库与匹配入队在同一业务事务中完成，重解析也通过统一入口更新。只有标题、发布时间、名称和剧集编号等推理输入变化才使旧结果失效；字幕抓取等独立元数据变化保留原结果。PostGraphile 隐藏通用写入口，避免绕过业务事务。直接 SQL 维护不会隐式匹配。

目录版本由规范化内容计算，权威快照和静默窗口截止时间保存在数据库。重启继续原有截止时间，配置变更只影响之后发现的目录变化。模型不使用逐集日期，因此逐集更新无需重建目录。

目录 active 与 desired 分开保存，使构建失败时仍保留可恢复基线。候选季度存在待生效变化时，匹配队头等待；无关季度变化不阻塞当前候选。构建期间暂停匹配，避免旧快照反向覆盖新 worker 缓存。缓存丢失时由 API 上传保存的 active 目录恢复，失败任务保留供显式处理。

候选按资源发布时间、公历季度、时区和相邻季度配置选择。完成结果不会因目录、模型或配置变化自动重评，避免无意改变既有业务关联。关闭匹配会暂停生产和消费，再启用时保留原队列但不补录停用期间的新种子。

## 结果与取消

模型正常拒答与组件故障分开：拒答完成为 NO_MATCH，故障保留 PENDING，由队列记录失败。结果只保存关联与必要版本诊断；季度被删除时关联置空，但历史 MATCHED 保留，避免把对象删除改写成模型拒答。

用户取消关联保存 DISMISSED，并与生产和结果提交采用相同锁顺序删除任务。在途旧结果无法覆盖取消意图，后续自动或批量重评也跳过已取消记录。

管理员可通过鉴权 `enqueueTorrentSeasonMatches` 分批指定 Torrent ID。默认仅处理未进入匹配的记录，rematch 显式允许重评；失败队头仍需按队列规则修复。该入口用于明确范围的维护任务。

## 验证重点

数据库回归覆盖事务回滚、并发入库去重、重解析失效、取消和旧 revision 提交。传输回归覆盖缓存丢失恢复、非法返回、请求取消及不确定结果；HTTP 请求不自动重试，以免掩盖目录状态变化。测试环境与命令见 [AGENTS.md](../AGENTS.md)。
