# API 与季度匹配器的边界

HTTP／JSONL 的类型、端点、错误和资源限制统一维护在[匹配器 v2 协议](../../../libs/anime-matcher/PROTOCOL.md)。API 使用 HTTP 传输，由服务管理器维护 worker 进程和模型资源。

数据库保存权威目录、待生效快照、静默窗口及队列；worker 只持有派生缓存。API 用规范化内容的 SHA-256 标识目录，上传成功后才激活新版本，缓存丢失时显式恢复。匹配请求的 `candidateIds` 提供近期候选，`catalogVersion` 标识此前已发布的完整目录；matcher 自行决定如何使用完整目录。近期候选为空时仍可继续匹配；完整目录为空时可以正常拒答。

传输超时可能发生在远端已激活目录之后，因此恢复先查询实际版本，再决定是否重传。API 校验核心协议版本、请求 ID、目录版本及结果是否属于完整目录。`modelVersion`、`mode`、阶段、诊断等均是可选扩展，API 不解释其结构，连同完整响应原样保存；本地另记录输入摘要。组件故障交给队列保留并处理。目录与结果提交的设计见[匹配流程](torrent-matching.md)。
