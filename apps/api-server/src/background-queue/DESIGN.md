# 单实例后台队列

队列将工作与业务写入放在同一事务中入库，避免业务成功却漏掉后台处理。处理器和调度策略由代码注册，数据库只保存未完成工作；业务检查点仍由所属模块维护。

同一通道的 key 合并为最新输入，revision 用于阻止旧执行提交新输入的结果。成功后删除任务，因此 key 只对未完成工作去重。payload 的格式版本独立于 revision；未知格式保留为失败，等待处理器升级或输入修复。

耗时或外部操作在事务外执行，返回的提交函数只做数据库写入。结果与当前 revision 的任务删除一起提交；输入已替换时，旧结果整体回滚。外部副作用可能已经发生，处理器必须能安全重放。

每个通道按 FIFO 消费未失败的任务。任务终止失败后保留记录并继续后续任务，重启后也跳过这些失败记录。等待中的依赖与延迟重试仍阻塞本通道，其他通道可以继续；有顺序依赖的处理器通过 `ready` 或 `QueueWaiting` 等待业务前置条件。

默认没有自动重试，业务可明确声明有限重试；继续消费的策略不跳过等待中的依赖或延迟重试。替换失败任务的输入不会自动重试，显式恢复后才重新执行。数据库故障导致状态无法保存时，进程内暂停通道，修复后重启以恢复未确认工作。

当前只支持单个 API 消费实例，重启会恢复未完成任务。扩展到多实例前必须先设计执行租约和外部副作用去重，不能直接增加副本。
