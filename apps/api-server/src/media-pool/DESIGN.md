# 媒体池与剧集版本

媒体池保留原件，版本描述完整的视频和字幕集合，当前版本表示已采用的文件。Jellyfin 识别状态仍由 `jellyfinEpisodeId` 表示，文件发布与播放关联分步提交。

## 文件身份与版本契约

每次独立导入给各文件生成 UUID，存储在 `root/files/UUID前两位/UUID`。相同内容、相同源路径的不同导入也各有身份；不按内容 hash 查找、合并或共享资产，不引入引用计数或垃圾回收。原件在替换、取消和删除季度后继续保留。下载位置允许多个独立资产记录同一来源；每个文件仍只有一个当前播放器位置。

`register()` 先准备所有池文件，再通过同一事务创建完整版本及文件关联。已创建版本的文件 UUID 集合、角色和相对布局不可变；内容变化创建新版本，是否采用由发布业务决定。明确沿用已登记 UUID 可以在新版本中引用该文件。相对路径以季度实际目录为根，拒绝绝对路径、空段、目录穿越和符号链接；`MediaAsset.jellyfinPath` 记录实际已发布位置，撤下后为空。

操作准备记录在复制或链接前持久化独立 UUID 和源身份，版本以任务/条目的 operationKey 幂等。准备中断复用记录中的 UUID；事务提交结果不明时先查询原版本，不能重新生成文件身份。硬链接通过 dev/ino、size/mtime 与普通文件检查验证，不读取全文件；复制必须比较源、目标 SHA-256，并检查整个操作期间身份未变。hash 只用于复制完整性验证。设备或 inode 超过安全整数范围时拒绝，避免舍入误认；连续 hash 不能保护原件日后被外部原地修改。

## 采用、差量发布与恢复

准备独立版本不取得同集发布权，也不恢复其他任务现场。取得发布权后才切换文件与当前版本，占用持续覆盖元数据、异步 Jellyfin 刷新和播放关联提交。失败保持占用；重试或取消完成后才允许交接，任务版本/尝试校验阻止迟到回调。短事务仅持有任务行与剧集锁，不跨外部调用持锁。

按目标路径及明确 UUID 分为保留、新增、替换、移除。相同路径与 UUID 的文件校验后原位保留，维持原外部关联、链接及 identity；只有变化项准备暂存、备份并进入 `media_publications` 日志。日志记录操作当时的绝对路径与身份，在目标变化前持久化。数据库事务更新变化项、当前版本和提交标记；提交前失败回滚，提交后只清理。无法确认数据库结果或发现外部改写时保留现场，禁止猜测恢复。

目录改名与发布恢复、版本准备及删除共用串行队列。有进行中或失败任务时拒绝改名/删除。改名前先处理相关发布日志，再持久化目录移动日志，记录源/目标绝对路径和目录身份。目录移动后同一事务迁移实际外部位置、任务产物路径和季度实际目录；中断后按原日志完成，后续操作先恢复该日志。历史版本布局与池路径保持不变，重新发布旧版本使用季度最新实际目录。删除季度先撤下当前文件，再清理目录，最后删除版本及季度，原件继续保留。

## 启动与历史登记

当前协议只支持单 API 实例，部署时停止旧实例，先执行唯一最终 schema migration，再启动新实例；没有运行时分布式租约或数据库写入开关。`MediaWriteState` 单例默认 initializing，HTTP 入口、文件服务及任务启动共同使用。预检有 30 秒边界，从下载器和媒体库实际配置取得映射后目录，通过自建临时文件验证权限与硬链接。仅 EXDEV 且显式开启 `mediaPool.painfullyAcceptCrossDeviceCopy` 时允许复制。失败日志附[用户迁移指南](https://std4453.github.io/lani/docs/installation/media-pool-migration)，受控关闭后非零退出。

HTTP 监听成功后才启动受管理的后台登记，启动钩子不等待全量回填。后台先恢复文件日志，再逐集从 Jellyfin 已有关联查找视频及外挂字幕，不移动用户文件，不改写播放关联或历史任务，来源记录 unknown。查询与原有播放不受登记耗时影响；进度通过 `mediaRegistrationProgress` 查询，计数从已有业务记录推导，不建进度表。成功后开放写入并恢复任务；瞬时网络/数据库故障最多重试两次，不可恢复错误关闭写入、记录原因并受控退出。重启从业务记录继续，独立但内容相同的历史文件均可登记。

内部媒体表对 PostGraphile 隐藏，当前版本字段禁止原生 mutation 改写。本期不新增前端界面。
