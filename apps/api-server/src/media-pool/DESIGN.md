# 媒体池与剧集版本

媒体池保留原件，版本描述完整的视频和字幕集合，当前版本表示已采用的文件。Jellyfin 识别状态仍由 `jellyfinEpisodeId` 表示，文件发布与播放关联分步提交。

## 文件身份与版本契约

每次独立导入给各文件生成 UUID，存储在 `root/files/UUID前两位/UUID`。相同内容、相同源路径的不同导入也各有身份；不按内容 hash 查找、合并或共享资产，不引入引用计数或垃圾回收。原件在替换、取消和删除季度后继续保留。下载位置允许多个独立资产记录同一来源；每个文件仍只有一个当前播放器位置。

`register()` 先准备所有池文件，再通过同一事务创建完整版本及文件关联。已创建版本的文件 UUID 集合、角色和相对布局不可变；内容变化创建新版本，是否采用由发布业务决定。明确沿用已登记 UUID 可以在新版本中引用该文件。相对路径以季度实际目录为根，拒绝绝对路径、空段、目录穿越和符号链接；`MediaAsset.jellyfinPath` 记录实际已发布位置，撤下后为空。

操作准备记录在复制或链接前持久化独立 UUID 和源身份，版本以全局唯一的 `registrationKey` 作为版本登记的幂等标识，自增整数 `id` 表达版本身份，不维护额外序号或来源字段。准备中断复用记录中的 UUID；事务提交结果不明时先查询原版本，不能重新生成文件身份。硬链接通过 dev/ino、size/mtime 与普通文件检查验证，不读取全文件；复制必须比较源、目标 SHA-256，并检查整个操作期间身份未变。hash 只用于复制完整性验证。设备或 inode 超过安全整数范围时拒绝，避免舍入误认；连续 hash 不能保护原件日后被外部原地修改。

## 采用、差量发布与恢复

准备独立版本不取得同集发布权，也不恢复其他任务现场。取得发布权后才切换文件与当前版本，占用持续覆盖元数据、异步 Jellyfin 刷新和播放关联提交。失败保持占用；重试或取消完成后才允许交接，任务版本/尝试校验阻止迟到回调。短事务仅持有任务行与剧集锁，不跨外部调用持锁。

按目标路径及明确 UUID 分为保留、新增、替换、移除。相同路径与 UUID 的文件校验后原位保留。atom 通过已保存的 `mediaVersionId` 重放：已完成的硬链接按 inode 跳过，已移除文件视为完成，其余继续执行；允许中断期间新旧文件暂时混合。文件全部达到目标状态后，由 atom 的短事务一起提交当前版本、实际位置/身份和完成检查点。提交前中断继续完成目标版本；取消取得发布权的任务也先完成目标文件状态，再由 runner 结束取消和释放占用。

复制采用登记标识与 UUID 确定的暂存名，验证内容后再替换。暂存 inode 保留到数据库确认提交，供重试核对已复制目标的归属；未发布的半份暂存可从头复制。外部修改导致身份不符时停止，不能仅凭同名覆盖。无专用发布日志表、逐文件检查点或整组备份回滚。

季度服务负责改名、删除与恢复，和版本操作共用 `MediaOperations` 串行边界。有进行中或失败任务时拒绝改名/删除。改名前持久化目录移动记录，文件工具仅处理路径与目录身份；移动后季度事务调用任务模块迁移普通/批量产物路径，调用媒体池迁移实际位置，再更新季度记录。任务模块在调用方事务中锁定任务行，避免批量 JSON 丢失并发更新。中断后按原绝对路径与目录身份完成同一提交，后续媒体操作先恢复。历史布局与池路径不变，旧版本重新发布时使用最新实际目录。删除直接幂等递归清理实际目录，成功后事务清空资产外部位置、当前版本并删除版本及季度；失败保留定位和关联供重试，原件继续保留。

## 启动与历史登记

当前协议只支持单 API 实例，部署时停止旧实例，先执行唯一最终 schema migration，再启动新实例。启动协调器在 HTTP 监听和定时任务启动前完成环境预检、媒体池初始化与季度移动恢复。预检有 30 秒边界，仅检查媒体池与映射后的 Jellyfin 库目录，通过自建临时文件验证权限与硬链接；下载路径的链接能力在实际下载导入流程中检查。仅 EXDEV 且显式开启 `mediaPool.painfullyAcceptCrossDeviceCopy` 时允许复制。失败日志附[用户迁移指南](https://std4453.github.io/lani/docs/installation/media-pool-migration)，受控关闭后非零退出。

预检与中断恢复完成后，任务服务在 `OnApplicationBootstrap` 中恢复待处理任务一次；HTTP 监听后，协调器启动受管理的后台登记，不等待全量回填。回填服务位于媒体池模块之外，仅查询 `jellyfinEpisodeId != null && currentVersionId == null` 的剧集，通过既有 `UserLibraryService.getItem` 和注入的 `AxiosService` 获取视频与外挂字幕；超时和错误转换沿用统一接入层。无待登记剧集时不请求详情。回填模式不记录下载来源，也不移动用户文件或改写播放关联与历史任务。

无需全局写入开关：发布在 `MediaOperations` 互斥内读取剧集当前状态，暂缓待回填剧集的替换；季度服务在同一互斥内检查该季度是否仍有待回填剧集，再执行改名或删除。无关剧集可以下载、准备和发布，查询与原有播放继续可用。目录移动恢复依据已持久化的现场完成，不受回填条件阻止。单集登记完成后相关限制自然解除，同集跨步骤发布互斥仍由任务维护。

进度通过 `mediaRegistrationProgress` 查询，从已有业务记录推导，不建进度表。瞬时网络/数据库故障最多重试两次，不可恢复错误记录原因并受控退出。关闭时停止继续枚举和登记，进行中的请求由接入层超时约束。重启从业务记录继续，独立但内容相同的历史文件均可登记。

内部媒体表对 PostGraphile 隐藏，当前版本字段禁止原生 mutation 改写。本期不新增前端界面。
