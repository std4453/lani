# 下载任务的恢复设计

任务在创建时保存有序流程快照，执行器按该快照推进，后续修改流程定义不会改变已有任务。下载入口负责选源、去重和业务参数，通用任务层负责持久化、取消、重试及恢复。共享协议见 [`@lani/workflow`](../../../../libs/workflow/README.md)。

## 事务与外部副作用

业务写入与检查点需同时提交时，使用任务上下文提供的短事务。锁顺序固定为任务行再剧集行；上下文校验当前版本、步骤和尝试编号，防止迟到结果覆盖新的执行。文件复制、下载器调用及媒体服务等待在事务外完成，通过检查点实现重放。

发布剧集关联与发布检查点在同一事务提交，任务收尾可以随后恢复。取消保留已经发布的关联、媒体文件和下载数据。通知使用进程内事件，关联提交后进程退出可能导致通知及 Lania 入队遗漏；需要持久投递时应另行设计事务消息。

取消先保存永久意图，再等待在途操作收敛并逆序清理。清理失败后仍由同一重试入口继续取消。下载器添加结果不明时，单次查询未找到种子不足以确认取消成功；删除后也需回查。

## 身份与恢复

内容 hash 与下载器 ID 分开保存。qBittorrent/libtorrent 对 hybrid 资源可能使用截断的 v2 ID，而只含 btih 的磁力链接取得元数据后 ID 可能变化；查询保留历史 v1 回退，文件操作使用下载器实际 ID。查询失败不能当作种子不存在。

下载和导入先登记独立媒体版本，原件保留。采用版本时按 UUID 与路径幂等执行差量文件操作，再将当前版本、实际文件身份和 atom 完成检查点一起提交；中断后继续完成目标版本。跨步骤的同集发布占用由任务维护，覆盖元数据、播放器刷新及关联提交，详见[媒体池设计](../media-pool/DESIGN.md)。

整季下载先读取 torrent 文件预览，用户确认后固定文件与剧集映射，提交时重新校验资源身份。下载器下载完整种子，映射决定导入范围。既有种子的路径布局与预览不一致时应明确失败，按同名文件猜测会导入错误内容。批量检查点与导入共用，详见[导入任务说明](../../docs/import-tasks.md)。

当前任务执行按单 API 实例设计。旧任务保留只读展示，未完成的旧流程标记失败并要求重新创建，以免按新流程误恢复。
