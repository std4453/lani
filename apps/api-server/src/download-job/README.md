# 可控下载生命周期

## 概念与职责

- **Workflow**：任务创建时保存的有序流程快照，包含步骤、依赖、检查点和执行状态；共享协议位于 `@lani/workflow`。
- **Task**：持久化的任务实例。`TaskService`、`TaskStore` 和 `WorkflowRunner` 统一负责创建、查询、取消、重试、恢复及串行执行，不按任务类型选择运行时。
- **DownloadJob**：下载业务入口，负责剧集与种子参数、同集下载去重及自动选源，再交给 Task。默认定义包含提交、下载、查找文件、导入、元数据、播放器刷新和发布剧集七个原子，执行器不依赖此数量或顺序。

共享原子位于 `task/atoms`，下载器客户端独立位于 `download-client`。任务的 `type` 包含 `DOWNLOAD`、`IMPORT`、`BATCH_IMPORT` 和 `BATCH_DOWNLOAD`，用于业务标识和前端详情入口，不参与执行调度。快照分别记录协议版本与流程定义版本，之后修改定义不改变已有任务。当前沿用单个 API 实例执行任务，不提供跨实例执行租约。

Prisma 模型为 `Task`，通过 `@@map` / `@map` 保留 `download_jobs` 表和所有物理列名；PostGraphile 用 `@name` smart comment 提供 `Task`、`allTasks`、`taskById` 和 `tasksByEpisodeId`。旧物理 `status` 只表示兼容阶段，对外命名 `legacyStage` / `LegacyTaskStage`，运行状态以 Workflow 为准。GraphQL 名称随前后端同步发布，不保留旧查询和 mutation 别名。

## 状态与恢复

需要数据库业务写入与检查点共同提交的原子使用 `context.transaction(async ({ tx, saveCheckpoint }) => { ... })`。上下文统一获取任务行锁并校验执行尝试，回调提供的 `saveCheckpoint` 已绑定同一事务；事务回滚不会更新内存检查点。回调保持为短事务，外部服务等待和文件复制留在事务外。剧集锁由业务 util `lockEpisode` 提供，始终在任务行锁之后获取，发布占用保存在调用原子的检查点内。

每次状态提交校验任务行版本，执行上下文另校验当前步骤和尝试编号。成功产物和下一步状态一起提交；失败重试只运行当前步骤。重启时对仍在执行的步骤调用 `recover`，默认实现通过同一幂等执行逻辑和检查点恢复，原子可以覆盖恢复钩子。`publishEpisode`（下载完成）原子在独立事务内提交剧集 Jellyfin 关联和发布检查点，以明确区分识别到条目与实际发布；同一关联重复执行直接返回，不重复通知。关联与任务收尾分开提交，因此发布后重启可重试收尾，取消不会撤回已发布关联。发布事件沿用进程内通知，不引入事务消息机制；若进程在关联提交后、事件发出前退出，用户通知及依赖该事件的 Lania 入队可能遗漏，不保证持久化投递。

取消先保存永久意图，再等待在途操作收敛并逆序调用已执行原子的取消钩子。后续步骤显示已取消，已完成步骤保留成功状态。取消失败仍为失败，界面按钮统一为“重试”，接口根据取消意图继续清理。重复取消不会自动重试失败的清理。

种子 hash 在请求添加前保存。添加结果不明时不能因查询一次不存在而报告取消成功；查到种子后先保存确认检查点，再删除条目并回查。删除固定保留数据，不检测共享种子。若添加结果始终无法确认，保持失败并等待重试。

种子文件支持 v1、v2 和 hybrid，磁力链接支持 `btih` 与 `btmh`。提交检查点的 `hash` 保留内容身份（有 v1 时优先 v1，否则完整 v2）。解析时另行计算 `clientHash`：遵循 qBittorrent 4.5/4.6 配合 libtorrent 2 的 `get_best()`，已知 v2 时使用其前 40 位，否则使用 v1。请求添加前保存两者，并将 `clientHash` 写入任务的 `qbtTorrentHash`；确认后更新为下载器返回的实际 ID。

查询只接受下载器 ID 或历史 v1，先按 ID 合批，缺失时共用一次完整列表查询，通过 `infohash_v1` 找到对应种子。这个回退也处理仅含 `btih` 的磁力链接取得 hybrid 元数据后 ID 改变的情况。旧检查点没有 `clientHash` 时使用原 v1 hash，不批量回填历史任务或改写资源库 hash。纯 v2 的完整 hash 在解析阶段转换，不作为历史兼容分支放进查询逻辑。

状态与进度结果保留请求标识，文件查询与删除使用实际 ID；查询失败继续抛错，不当作种子不存在。删除后按原标识及实际 ID 回查，不能仅凭删除接口返回成功判定取消完成。

文件先暂存并记录身份，再以不覆盖目标的方式发布；纯复制和纯移动策略不依赖硬链接。移动策略只在发布后移除源文件，重启可通过已记录的暂存身份确认成果。取消保留已落地媒体和下载数据，不撤回已发送的 Jellyfin 刷新。复制等不可中断操作必须收敛后才能报告取消成功。

导入、写元数据、播放器识别和发布剧集 atom 按需调用 `claimEpisodePublication`，以短数据库事务检查同集发布占用；通用执行器不包含互斥规则。其他任务占用、已成功发布或目标文件归属不符时直接失败，不排队竞争。

旧任务不回填流程，也不恢复执行；未结束的旧任务在启动时标记失败，原因为“旧版任务已失效，请重新创建”，重试返回“旧任务不允许重试”。

下载与播放器 atom 分别向 `DownloadRefreshService`、`PlayerRefreshService` 入队。下载每 30 秒按 hash 合批查询，查询异常只记录警告并保留等待对象，下个周期自动重查；Jellyfin 每 15 秒按季度合批查询，新入队剧集共同触发一次季度刷新。手动刷新复用同一个在途批次，取消或失败会移出队列，旧批次不能完成新尝试。

## 接口与验证

- `cancelTask(taskId)`：请求永久取消。
- `retryTask(taskId)`：重试执行或取消，拒绝旧任务。
- `getTaskStates(taskIds)`：批量获取类型化流程、兼容字段和操作能力。
- 列表变化检查复用 `allTasks`，使用与列表相同的筛选和分页，仅查询 ID 与总数。
- `getDownloadProgress(taskIds)` 查询下载进度；空 ID 集合不查询下载器，手动刷新保持批量处理。

共享协议和执行器测试使用内存 store；文件恢复测试使用临时目录。数据库集成测试仅在设置 `LANI_LIFECYCLE_TEST_DATABASE_URL` 时运行，要求本机隔离数据库且名称以 `_test` 结尾。先准备与 Prisma schema 一致的测试数据库，再运行：

```bash
rushx test --runInBand
LANI_LIFECYCLE_TEST_DATABASE_URL=postgresql://test@127.0.0.1:5432/lifecycle_test rushx test --runInBand --testPathPattern download-job/index.service
```

禁止将集成测试指向共享环境。Schema 生成按开发指南进行，不手工修改 Admin 的生成类型。

## 前端与刷新

通用详情入口接收 `taskId` 与 `taskType`，直接渲染对应业务弹窗。下载弹窗内部定位关联剧集，保留剧集标题、头部信息和同集任务切换；加载时在同一个弹窗内显示骨架，缺失关联的提示也由业务弹窗处理。下载进度使用独立组件。

Admin 的 `TaskWorkflow` 按快照顺序渲染，atom 注册表只选择 JSX 展示组件。弹窗使用步骤样式，任务信息与成功步骤可展开、收起，当前执行、失败或取消位置始终展示对应内容。滚动区只在步骤进行中或刚切换步骤时自动定位，手动滚动及展开、收起操作后等待 5 秒。旧任务通过只读展示适配器复用相同步骤组件，不回写流程或推算历史时间。

任务列表使用彩色步骤 Tag 和圆点状态：正常、运行中、运行失败、取消。运行中合并执行中与取消中，运行失败合并执行失败与取消失败；正常任务固定显示“可用”，已取消任务的步骤显示“－”。列表及轻量集合检查共用 GraphQL 筛选条件，失败原因单行省略，悬停显示保留换行的完整内容。

任务发现与列表集合检查每 30 秒执行，活动任务状态每 3 秒执行，展开的下载步骤每 2 秒读取进度。页面隐藏、离线、弹窗关闭或没有目标时停止对应轮询；恢复前台或联网立即刷新。状态查询串行化，终态退出高频查询，列表只合并当前行的状态，集合变化由用户点击更新。

共享协议测试位于 `libs/workflow`，前端测试位于 `apps/admin`，分别在包目录运行 `rushx test --runInBand`。GraphQL 生成必须同时包含 data 和 API 的 Federation schema，`Workflow` scalar 映射到共享协议类型。


## 整季下载

`previewTorrent(torrentId)` 读取数据库中的种子地址，解析并一次性返回完整文件列表。此时不向下载器添加种子、不创建任务，也不持久化识别结果；内存预览保留 15 分钟，最多 100 项，重启或缓存淘汰后需要重新选择种子。磁力链接不能在不提交下载器的前提下读取文件列表，因此预览要求资源提供 torrent 文件。

`downloadTorrentForSeason(seasonId, previewToken, entries)` 校验所选视频属于预览、文件和剧集没有重复、全部剧集属于指定季度，再在同一事务中创建任务和关联。`batchEntries` 保存种子内相对路径及用户确认的映射；提交时重新读取种子并核对预览身份，链接内容变化时失败。已有相同 hash 的下载器任务继续复用，已完成的种子直接进入查找文件步骤。

整季任务沿用下载七步流程；查找文件按映射精确匹配下载器文件名，不再执行单集的大小占比推断，文件缺失时报告具体剧集。后续导入、写入元数据、刷新 Jellyfin 和发布均复用批量导入的逐项检查点、失败重试与取消行为。下载器会下载整个种子，所选文件决定导入范围。部署需要执行新增 `BATCH_DOWNLOAD` 枚举值的 Prisma 迁移。
