# 任务执行器的边界

任务执行器负责流程快照、版本与尝试编号、检查点、取消清理、重试和重启恢复。选源、超时策略、替换条件等业务决策由调用方或具体 atom 负责，避免调度器依赖某种下载策略。流程协议见 [workflow](../../../../libs/workflow/DESIGN.md)，下载领域约束见[下载恢复设计](../download-job/DESIGN.md)。

外部调用方通过 `TaskService.cancel` 取消任务；atom 在自身执行中确定需要终止时，抛出 `TaskCancellation` 通知执行器。两种入口均复用协议中的取消状态转换，先持久化意图，再逆序调用已执行 atom 的清理方法。取消原因与可选的字符串 code 由业务调用方提供，通用任务层只保存和传递，不枚举具体业务原因。

取消清理失败仍保留原取消意图，重试继续清理。迟到的 atom 结果只对原来的步骤与尝试有效，不能取消重试后的流程或覆盖其产物。已有的 `ExecutionStopped` 仅表示本轮执行失效，不新增任务取消意图。
