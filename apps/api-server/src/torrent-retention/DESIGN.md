# 种子清理设计

清理依据 Lani 下载任务确认的种子归属，避免用户修改下载器分类或标签后误删外部任务。未确认提交、仍被活动任务使用、或删除历史后无法确认归属的种子均保留。删除操作固定保留文件，媒体及任务历史继续由各自流程管理。

qBittorrent 没有“达到分享率后停止时间”。暂停/停止与做种使用不同保留期，但都从完成时间起算，缺失时回退添加时间。累计 seeding_time 无法代表状态切换时刻；手动暂停与自动停止也无法仅凭状态区分。

扫描与下载进度轮询分离，候选经[后台队列](../background-queue/DESIGN.md)持久化。执行前重新核对归属、活跃使用、状态和时间，减少扫描与删除之间的状态变化风险。批次失败留待下一次扫描；损坏 payload 保留为失败任务，修复并显式恢复前不再扫描；队列数据库故障会暂停消费。

请求分批串行执行，每批最多 100 个 hash，URL 编码后的表单小于 8 KiB。这既远低于 qBittorrent 4.6.7 的 64 MiB 请求限制，也为反向代理留出余量。删除接口成功只代表请求被接受；重启后可自然跳过已不存在的种子。
