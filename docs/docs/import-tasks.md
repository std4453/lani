# 下载和导入任务

下载、单集导入、批量导入共用任务管理、后台执行、取消和重试。导入接口创建任务后立即返回任务 ID；关闭详情弹窗不会停止任务。批量导入只能选择同一季度的不同剧集，源路径也不能重复。

## 关联与恢复

`Task` 保存任务类型、workflow、种子信息和下载根目录。`TaskEpisode` 按 `position` 保存最终确认的剧集映射、导入源路径、视频路径、目标路径、NFO 路径和 Jellyfin 剧集 ID。下载和单集导入各有一条关联，批量任务有多条。删除剧集只清空关联中的剧集 ID，保留任务和产物。

导入步骤依次为：寻找视频文件、导入文件、写入元数据、刷新 Jellyfin、完成。每步等待所有文件操作结束，有任一失败就不进入下一步。检查点保存到 `workflow.steps[].checkpoint.entries[关联 ID]`，每项成功后设置 `completed`；重试跳过已成功项。任务行锁和版本检查保证并发更新不会覆盖其他项的检查点或产物。

取消唤醒所有等待项，并等待在途文件操作收敛；已经落地的文件和已经发布的关联保留。暂存文件和 Jellyfin 等待项按任务、关联区分，迟到结果不能写入新尝试。下载和导入共享剧集发布互斥，不覆盖其他任务的产物。导入完成不发送下载发布事件，不触发下载通知或 Lania 发布同步。

## 自动偏移

偏移只产生确认表单初值，不自动提交。最终映射在创建任务时保存，执行与重试不重新推断。手工改映射或删除确认行不会触发重新匹配；删除行不改变上一步的文件选择。可用“恢复原编号”取消偏移。

约定 `目标编号 = 文件编号 − d`。选择至少 6 个文件且识别出至少 6 个不同的普通单集编号时才推断非零偏移。普通 `.5` 编号参与匹配；SP、OVA、OAD 使用各自类型直接匹配，范围和无法解析的文件交给人工。重复普通编号阻止自动偏移。

候选包含零及所有整数差值。候选必须让全部已识别普通文件一一对应实际存在的季度剧集；越界、编号空洞均无效，不裁掉离群文件。读取完整季度，编号优先使用 `episodeNumber`，缺失时兼容 `index`。

缺集集合 M 为没有可用媒体且没有进行中任务的普通剧集；失败、已取消任务不阻止计入 M。候选目标集合为 T，文件数为 n，评分为：

| 分项           | 分数                                   |
| -------------- | -------------------------------------- | --- | ------ | --- | --------------- |
| 缺集命中率     | `40 ×                                  | T∩M | / n`   |
| 缺集覆盖率     | `10 ×                                  | T∩M | /      | M   | `，M 为空时为 0 |
| 季度边界       | 命中首、末编号各加 3                   |
| 接近 12 倍数   | `8 × (1 − distance(d, 12ℤ) / 6)`       |
| 原编号         | d 为 0 时加 8                          |
| 偏移距离       | `−min(8,                               | d   | / 48)` |
| 进行中任务冲突 | `−20 × 目标中运行中或取消中任务的比例` |

最高分为零时保留原匹配；非零候选只有在 `|d| ≥ 6` 且领先第二名至少 8 分时才自动应用，唯一有效候选无分差限制。±1 ～ ±5 仍参与排名，但不会自动应用，也不会跳过它们选择较低分的大偏移。无有效候选或分差不足时，仅保留原编号能精确匹配的行。

回归用例包括动物狂想曲历史映射的 12、刃牙道历史映射的 13，以及结构派生和人工构造的 11、60、−12、不连续缺集、歧义缺集、小偏移、元数据空洞、离群文件和重复编号。22 个场景与 29,568 组边界检查用于验证规则，不代表真实资源匹配准确率。

## 迁移与接口

迁移 `20261016000000_task_episodes` 将现有下载任务的剧集和逐集产物移到关联表，然后移除 Task 上的旧物理列。没有 workflow 的历史任务继续展示；已有 workflow 的单集根检查点通过投影恢复，不改写历史快照，也不回填历史同步导入记录。

GraphQL 的旧单集字段保留为基于关联表的只读投影。新的关联查询使用 `taskEpisodesByTaskId`；反向任务查询兼容 `tasksByEpisodeId`。原来基于外键生成的关联筛选和排序应改用任务—剧集关系。`importSingle`、`importMultiple` 返回值从同步结果改为 `Int` 任务 ID，调用方应打开任务详情查询执行结果。

发布时需停止旧 API worker 后迁移，并同时更新 API、Data Server 和 Admin；迁移后的数据库不能继续运行依赖旧物理列的代码。本次没有新增运行配置。

## 验证

除各包 Jest 测试及 Rush 构建外，在隔离的本地、数据库名以 `_test` 结尾的 PostgreSQL 上运行：

```bash
LANI_LIFECYCLE_TEST_DATABASE_URL='postgresql://localhost/example_test' \
  node libs/db/tests/task-episodes-migration.cjs

cd apps/api-server
LANI_LIFECYCLE_TEST_DATABASE_URL='postgresql://localhost/example_test' rushx test --runInBand
```
